MeterFlo Mobile API Documentation
Base URL
All endpoints require authentication. Pattern: /api/projects/:projectId/...

Authentication
Session-based authentication using cookies. The mobile app must maintain session cookies after login.

Sync Endpoints
Download Work Orders
GET /api/projects/:projectId/mobile/sync/download
Query Parameters:

lastSyncTimestamp (ISO date) - Only return records updated after this time
assignedUserId (string) - Filter by assigned user ID
assignedGroupId (string) - Filter by assigned group name
status (string) - Filter by status
includeCompleted (boolean) - Include completed work orders (default: false)
limit (number) - Pagination limit
offset (number) - Pagination offset

Upload Work Order Updates
POST /api/projects/:projectId/mobile/sync/upload
Request Body:

{
  "updates": [
    {
      "id": 123,
      "clientUpdatedAt": "2025-12-27T10:00:00Z",
      "serverUpdatedAt": "2025-12-27T09:00:00Z",
      "forceOverwrite": false,
      "data": {
        "status": "In Progress",
        "notes": "Started work"
      }
    }
  ]
}
Response:

{
  "success": true,
  "results": {
    "successful": [123],
    "conflicts": [
      {
        "id": 456,
        "serverVersion": {...},
        "message": "Server has newer data"
      }
    ],
    "errors": []
  }
}
Conflict Handling: Server rejects updates when serverUpdatedAt doesn't match current server value. Set forceOverwrite: true to override.

Work Order Operations
Claim Work Order
POST /api/projects/:projectId/work-orders/:workOrderId/claim
Assigns work order to current user and clears any group assignment.

Response:

{
  "message": "Work order assigned to you",
  "workOrder": {...},
  "claimed": true
}
Complete Meter Changeout
POST /api/projects/:projectId/work-orders/:workOrderId/meter-changeout
Content-Type: multipart/form-data

Form Fields:

photos - File array (up to 20 photos)
data - JSON string with changeout data:
{
  "canChange": true,
  "troubleCode": null,
  "troubleNote": null,
  "oldMeterReading": "12345",
  "newMeterId": "NEW123456",
  "newMeterReading": "00000",
  "gpsCoordinates": "40.7128,-74.0060",
  "signatureData": "data:image/png;base64,...",
  "signatureName": "John Doe",
  "photoTypes": ["before", "before", "after", "after"]
}
Photo Types: "before", "after", "trouble"

For Trouble Reports:

{
  "canChange": false,
  "troubleCode": "TC001",
  "troubleNote": "Meter locked in cabinet",
  "photoTypes": ["trouble"]
}
Bulk Operations
Bulk Claim
POST /api/projects/:projectId/mobile/work-orders/bulk-claim
Request Body:

{
  "workOrderIds": [1, 2, 3, 4, 5]
}
Response:

{
  "success": true,
  "results": [
    {"id": 1, "claimed": true},
    {"id": 2, "claimed": false, "message": "Already assigned to you"}
  ],
  "summary": {
    "total": 5,
    "claimed": 4,
    "skipped": 1
  }
}
Bulk Status Update
POST /api/projects/:projectId/mobile/work-orders/bulk-status
Request Body:

{
  "workOrderIds": [1, 2, 3],
  "status": "In Progress"
}
Photo & Signature Upload
Upload Photos
POST /api/projects/:projectId/mobile/work-orders/:workOrderId/photos
Content-Type: multipart/form-data

photos - File array
photoTypes - Array matching files: ["before", "after", "trouble"]
Upload Signature
POST /api/projects/:projectId/mobile/work-orders/:workOrderId/signature
Request Body:

{
  "signatureName": "John Doe",
  "signatureData": "data:image/png;base64,..."
}
Or upload as file with multipart/form-data using field name signature.

Important Notes
Meter Readings: Database stores as INTEGER - leading zeros are stripped. Client should handle display formatting.

Foreign Key Constraints:

updated_by and created_by → reference users.username
completed_by and scheduled_by → reference users.id
Offline Sync Pattern:

On app start: Call download with no lastSyncTimestamp for full sync
On subsequent syncs: Use serverTimestamp from previous response as lastSyncTimestamp
Queue changes locally, upload when online
Handle conflicts by showing user both versions
Webhooks: Automatically triggered on work order completion if project has webhookUrl configured. External systems receive real-time notifications.

GPS Format: String with comma-separated lat/lng: "40.7128,-74.0060"

Signature Data: Base64 encoded PNG with data URI prefix: "data:image/png;base64,..."
